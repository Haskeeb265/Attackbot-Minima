# =============================================================================
# Public resolver candidates (seed list)
# =============================================================================
# These are CANDIDATES, not truth.  Every entry is probed at run time by
# active/resolvers.py before it is used, because published resolver lists rot
# fast: the list bundled with massdns (8,477 addresses, ~2019) resolved
# nothing at all when tested, and a hand-checked 60-address sample of it was
# ~88% dead.
#
# Each resolver must pass two probes to make the working pool:
#
#   1. POSITIVE - it resolves a name that definitely exists.
#   2. NEGATIVE - it returns NXDOMAIN for a random label under `.invalid`
#      (RFC 6761 reserves that TLD and forbids it from ever resolving).
#      A resolver that *answers* the negative probe is hijacking NXDOMAIN
#      (captive portals, ISP search pages, ad-blocking wildcards) and is
#      rejected: on a hijacking resolver, "this wildcard is real" and "this
#      resolver invents answers" are indistinguishable.
#
# Deliberately a mix of filtering and unfiltered resolvers.  Filtering
# resolvers (AdGuard, CleanBrowsing, Quad9's filtered set, ...) can return
# NXDOMAIN for names in their blocklists, but resolution is satisfied when ANY
# resolver answers, and this pool always contains unfiltered members - so a
# filtered answer can only ever cost a duplicate query, never a missed host.
#
# Format: one IPv4 address per line; `#` starts a comment; blank lines ignored.
# Validated output is written to active/output/resolvers.txt, never edited here.
#
# Want more capacity?  Append addresses (or a maintained list such as
# github.com/trickest/resolvers) to this file, or pass --resolvers at run time.
# =============================================================================
