# Vuln engine R&D refresh — September 2026

An independent second pass, deliberately not anchored to the first list
([`RnD.md`](./RnD.md), [`feasibility_notes.md`](./feasibility_notes.md)).
The first pass was written around *agent planning* papers; this one starts
from what the 2025–2026 offensive-security literature says the field has
actually learned since — including from systems that now operate at bug
bounty scale — and maps every finding onto what Attackbot's recon side
actually emits today (`graph_state.json`, receipts, scope engine, dispatch,
stealth).

Same ground rule as before: **no architectural decisions here.** Status
legend: **sound** / **sound with caveats** / **speculative** / **challenged**.
Sources marked ✦ were read in full; everything else is verified from the
paper's abstract/metadata plus at least two independent secondary sources.

## 0. Executive summary — the ten findings that matter

1. **The field moved from "can an LLM hack" to "why do agents fail, and what
   is invariant to model progress."** The largest 2026 failure study (28
   systems, 200 traces) splits failures into *Type A* (capability gaps —
   fixable with tooling, 42%) and *Type B* (complexity barriers — 58%, and
   largely **invariant to the underlying LLM**). ✦
2. **The root cause of Type B failures is missing real-time *task difficulty
   estimation*** — horizon, evidence confidence, context load, historical
   success. Difficulty-aware planning cut the Type B failure rate from 58%
   to 27% in controlled ablation. ✦
3. **Architecture gains built to compensate for 2023-era model limits
   (context summarization, RAG-for-tool-knowledge, role decomposition) are
   eroding as models improve** — performance spreads across systems
   compressed by half when backbones upgraded. *This directly devalues part
   of the first R&D list's bet on observation-summarization machinery.* ✦
4. **The convergent winner shape is a specialized-pipeline-per-vuln-class
   under a thin LLM orchestrator, with state held *outside* the context
   window.** AWE (specialized agents) matched a general-purpose agent's
   injection-class results using **98% fewer tokens (1.12M vs 54.9M)** and
   4× faster. Specialization beats raw model scale on cost — the decisive
   fact for an engine that pays real requests per probe. ✦
5. **Verification is now a first-class research subject.** Browser-backed
   exploit verification (script-execution/DOM-mutation evidence) and
   evidence-gated PoC validation (a Validation agent separate from the
   exploitation path) are the mechanisms the top XBOW performers use.
   This closes the biggest gap the first feasibility notes flagged. ✦
6. **LLM PoC generation is quantified**: 8–34% of web CVEs get a working
   PoC from public data alone; **68–72% with adaptive reasoning
   scaffolding** (CoT + ICL + feedback). 23 generated PoCs were accepted
   into NVD/Exploit-DB. This makes a CVE→template capability realistic —
   the prerequisite CrystalBall and Kuikka were waiting on. ✦
7. **A real-world head-to-head exists now**: an autonomous agent (ARTEMIS)
   placed 2nd against 10 human pentesters on a live enterprise network,
   9 valid findings at an **82% valid-submission rate**, beating 9 of 10
   humans. Precision — not volume — is the metric that made it credible.
   ✦
8. **XBOW topped the HackerOne US leaderboard (June 2025)** — first
   autonomous system to do so. Agentic bug bounty is no longer
   hypothetical; platform policy and human-review norms are still catching
   up (CSA has published disclosure-reform recommendations requiring
   human review of AI-submitted reports).
9. **Vulnerability prioritization got a new layer**: NIST's LEV metric
   (2025) estimates *past* exploitation probability from EPSS history; the
   industry stack is now CVSS → EPSS → KEV → SSVC → LEV →
   environment-validated proof. Critically, **EPSS is a late signal**:
   median EPSS movement is 121× larger *after* KEV listing than before —
   it confirms rather than warns. For a bug-bounty engine, upstream signals
   (public PoC, weaponization chatter, patch availability) move first.
10. **Agent-tooling security became its own research area** (MCP tool
    poisoning, cross-server tool shadowing, rug pulls) and offensive-agent
    ethics/governance got its first dedicated papers. Any multi-tool vuln
    engine inherits this threat surface whether or not it uses MCP. ✦ (partly)

## 1. What changed since the first R&D list

The first list (GoalAct, STRUCTUREDAGENT, GraphAgent, TheoryCoder-2,
SymAgent, CrystalBall, VulnBot, RL-for-pentest) was assembled before the
2025–2026 wave landed. Its *shape* — propose → validate → execute → verify
→ record — has since been **validated by the field's leading systems**, but
several of its bets need recalibration:

| First-pass bet | What 2025–2026 literature says |
|---|---|
| GoalAct's re-emitted linear plan as core loop | Tree/graph search with difficulty-aware pruning (EGATS + UCB) now outperforms linear replanning on long horizons; the feasibility notes' §10 prediction ("the tree subsumes the transcript") is what the top-scoring system actually built |
| STRUCTUREDAGENT's Observation Summarizer as "the single most load-bearing unbuilt piece" | The 2026 failure study shows summarization-for-context-capacity is a *transient* challenge — million-token models dissolve it; external **state stores** (structured memory outside the context) are what persist |
| GraphAgent as FP reducer | Superseded: FP reduction research moved to *verification mechanisms* (browser-backed execution, independent validation agents, LLM+SMT path-feasibility), not graph re-ranking |
| TheoryCoder-2's auto skill synthesis | 2025–2026 memory research (Memento, MemSkill, Memento-Skills) landed on a middle path: memory/case stores that improve behavior *without* fine-tuning and without auto-synthesizing code skills |
| CrystalBall waiting on CVE ingestion | LLM PoC/template generation from public CVE data is now quantified (68–72% with scaffolding); the prerequisite is cheaper than assumed |
| Kuikka probability scoring with "EPSS as prior" | Still sound, but EPSS's *lateness* (finding #9) means the prior should be multi-signal, not EPSS-only |
| "Semi-autonomous with human checkpoints works better" (2502.15506) | Confirmed at scale: ARTEMIS's 82% valid-submission rate and every credible production system use evidence-gated autonomy; fully-autonomous novel exploitation remains beyond current systems (PentestGPT v2 says so explicitly) |

The first list's papers remain useful references; the *center of gravity*
has moved from planning-prompt architectures to **measurement, verification,
and cost-bounded specialization**.

## 2. Capability-by-capability findings

### C1. Planning, orchestration, and the failure taxonomy ✦

**PentestGPT v2 — "What Makes a Good LLM Agent for Real-world Penetration
Testing?" (arXiv 2602.17622, NTU/UNSW/SMU, Feb 2026).** The most important
paper of this cycle. Read in full. Key content:

- Analyzed 28 LLM pentest systems (2023–2025); evaluated 5 open-source
  representatives (PentestGPT, AutoPT, PentestAgent, VulnBot, Cochise)
  across XBOW (104 web challenges), the PentestGPT benchmark (13
  HTB/VulnHub machines), and GOAD (5-host Active Directory).
- **Failure taxonomy** (200 traces, dual-coded): Type A = capability gaps
  (missing tool/incorrect syntax 26%, output parsing/knowledge 16%).
  Type B = complexity barriers (context forgetting 18%, premature
  commitment 16%, exploration–exploitation imbalance 12%, multi-step chain
  failures 12%). Failure mix tracks task depth: 68% Type A on 1–3-step
  tasks, **79% Type B on 5+ step chains**.
- **Task Difficulty Assessment (TDA)** — four measurable, real-time
  dimensions: *horizon estimation* (remaining steps), *evidence
  confidence* (certainty about current state), *context load*, *historical
  success rate* on similar branches. Augmenting any agent with difficulty
  assessment cut Type B failures 58% → 27%.
- **Evidence-Guided Attack Tree Search (EGATS)** — attack tree with UCB
  (upper-confidence-bound) node selection, TDI-guided mode switching, and
  evidence-based branch pruning; state maintained in an external Memory
  Subsystem with selective context injection by tree position.
- Results: 91% peak / 89% mean on XBOW (+49% relative over best baseline),
  12/13 machines rooted, 4/5 GOAD hosts. Ablations: tool layer dominates
  short-horizon tasks; TDA-EGATS and memory dominate multi-step ones.
- **The convergence finding**: existing architectures compensate for
  transient model limits; their gains compress (44% spread → 22.5% on XBOW)
  as backbones improve. Design for *persistent* challenges: long-horizon
  planning, exploration–exploitation decisions, state outside context,
  difficulty assessment.
- Honest limits (their own): novel/creative exploitation, adversarial
  environments with deceptive defenses, and multi-week campaigns remain
  beyond current capability.

**Transfer to Attackbot.** This paper reads like a critique written for our
codebase. The four TDA dimensions are *already collected* on the recon
side: evidence confidence ≈ the S2 scoring pass (6,815 nodes scored);
historical success ≈ the receipts ledger; context load is measurable; the
convergence loop's frontier ledger is a breadth signal. The genuinely new
capability the literature adds is **UCB-style selection over an attack
tree** — which is also exactly the "contextual bandit over
(technique × surface) with receipt-derived rewards" the first feasibility
notes flagged as missing (§10), now with published evidence at benchmark
scale. The scope engine's ALLOW/DEFER/DENY is a *stronger* gate than
anything in these papers, and DENYs-as-first-class-observations (a
first-pass caveat) remains our own work.

**Status: sound with caveats** — mechanism validated on CTF/XBOW/GOAD, not
on third-party production scope; benchmark-to-field transfer debt from the
first notes still applies.

**MAPTA — Multi-Agent Penetration Testing AI for the Web (arXiv 2508.20816,
Aug 2025).** Three roles: Coordinator (planning), Sandbox agents (per-job
Docker execution), Validation agent (converts candidate exploits into
verified PoCs by concrete execution, context-isolated per agent). 76.9% on
XBOW (80/104), 100% on SSRF and misconfiguration classes; generous compute
(54.9M tokens total). The **context isolation + evidence-gated validation**
pattern is the load-bearing idea; the cost is not (21× AWE's tokens).

**Status: sound for the validation-agent pattern; challenged as a cost
model.**

### C2. Specialized vuln-class pipelines and the cost argument ✦

**AWE — Adaptive Agents for Dynamic Web Penetration Testing (arXiv
2603.00960, NDSS LAST-X workshop 2026).** Read in full. The clearest
articulation of the architecture the field is converging on:

- **Specialized Agents Layer**: per-vulnerability-class agents encoding
  expert pipelines as deterministic state machines, with the LLM as a
  bounded payload *generator* inside them. The XSS agent's five-phase
  pipeline is the model: parallel canary injections → fine-grained DOM
  context mapping (quoted/unquoted attribute, JS string, raw HTML) →
  server-side filter inference (character transforms, blocked tag
  families) → constraint-aware LLM payload synthesis → **definitive
  browser verification** (script execution, DOM mutation, dialog triggers).
  Similar structured pipelines for SQLi, SSTI (engine-specific probes),
  command injection, XXE, SSRF, IDOR (authenticated differential testing),
  LFI.
- **Persistent memory**: short-term (tried payloads + outcomes, inferred
  filters, progress markers — *this is the receipt concept, already
  independently matched by Attackbot*) + long-term cross-target learning
  (effective bypass patterns, sanitization signatures, payload success
  rates).
- **Threat model matches bug bounty reality**: black-box HTTP only, benign
  registration for authenticated probing, ≤10-minute budgets, cost-bounded
  LLM use.
- Numbers: 51.9% XBOW overall (vs MAPTA 76.9%) but 87% XSS (+30.5% over
  MAPTA) and 66.7% blind SQLi (+33.3%) on injection classes; 53.1s average
  solve; **1.12M tokens / $7.73 vs MAPTA's 54.9M / $21.38**; mid-tier model
  (Claude Sonnet 4) vs MAPTA's GPT-5.
- Design principles, verbatim: *specialization over generalized reasoning;
  stateful memory-driven operation; verification rather than speculation.*

**Transfer.** AWE's specialized agents are the vuln-engine counterpart of
what the recon side already built as deterministic pipelines, and its
short-term memory is the receipts mechanism rediscovered. Its long-term
cross-target memory (bypass patterns, sanitization signatures) is the
*new* capability worth studying — it gives the TheoryCoder-2 "workflow
compounding" idea a cheaper, safer form: store what worked, not synthesized
code. The strict success criterion (flag retrieval through verified exploit
only) is the metric discipline the report layer should inherit.

**Status: sound with caveats** — injection-centric scope (their own
exclusion of business-logic and multi-step semantic flaws); benchmark-only
evidence; open source (github.com/stuxlabs/AWE).

### C3. Verification, PoC generation, and FP suppression ✦

This is where the 2025–2026 literature most directly answers the first
notes' gap list ("nothing on the list addresses *confirming* a candidate
vuln independently").

1. **Browser-backed verification** (AWE, above) — definitive evidence for
   classes whose manifestation is invisible to HTTP-only testing (XSS,
   DOM-based issues). Eliminates "entire categories of false positives."
   For Attackbot: a headless-browser evidence step is the difference
   between "reflected, looks like XSS" and a reportable finding.

2. **Independent validation agent** (MAPTA) — candidate exploit → verified
   PoC by concrete execution, with the validator context-isolated from the
   generator. Answers the closed-FP-loop objection in the VulnBot section
   of the first notes ("an LLM that both generates the exploit *and* judges
   success is a closed FP loop").

3. **LLM PoC generation, quantified ✦** — "A Systematic Study on Generating
   Web Vulnerability Proof-of-Concepts Using LLMs" (arXiv 2510.10148, IEEE;
   100 reproducible CVEs, CWE-79/89/352/78/434, ~3,000 trials):
   - description-only (0-day stage): **8%** working PoCs
   - with patch diff (1-day): ~34% (DeepSeek-R1 consistently > GPT-4o)
   - with function-level source context (N-day): 54% (DS-R1) / 38% (GPT-4o)
   - with CoT + in-context learning + real-time feedback: **68–72%**
   - 86.4% of failures trace to *missing navigation context* (file/layout
     structure) — context completeness is the success factor, not raw model
   - 23 generated PoCs accepted into NVD/Exploit-DB
   For Attackbot: (a) CVE→PoC→detection-template generation is feasible and
   cheap enough to schedule; (b) the study's benchmark (100 CVEs with
   ground-truth PoCs and staged public artifacts) is a ready-made eval
   corpus for a CVE-ingestion capability; (c) the "context completeness >
   model size" finding mirrors AWE's DOM-context inference — feed the model
   precise local structure, not more reasoning.

4. **The cautionary counterweight** — GreyNoise's "PoC Pollution Problem"
   (Jul 2025): AI-generated exploits are flooding public repos with broken
   PoCs that waste triage time and create detection blind spots; CSA's
   2026 whitepaper ("Automated Exploit Generation: LLMs Cross the
   Threshold") documents the same trend from the threat side. Consequence:
   *generated* PoCs are leads; only executed-and-observed PoCs are
   findings. (Matches the receipts rule: only conclusive attempts earn a
   skip.)

5. **FP suppression by hybrid LLM+static analysis** (from the code-side
   literature, transferable as a *pattern*): IRIS (LLM-assisted static
   analysis, 360+ citations), LLM4PFA (LLM+SMT path-feasibility filtering
   of static-analysis alarms, arXiv 2506.10322), VulnDetect AI (hybrid
   framework), Datadog's production LLM FP-filtering. The transferable
   pattern: **static/structural evidence picks the candidates; an LLM with
   precise local context adjudicates them** — the same shape as AWE's
   filter-inference→payload-synthesis step, and the same shape as Attackbot
  's scorer-then-LLM-enricher split.

**Status: sound with caveats.** Verification is the most de-risked
capability on this whole page; the residual risk is evidence-theft (a
verification step that itself mutates third-party state must pass the
dispatch gate like everything else).

### C4. Memory, skill libraries, and learning without fine-tuning

2025–2026 answer to the TheoryCoder-2 question ("can the engine compound
experience?") — the field converged on **memory-as-state, not
skills-as-code**:

- **Memento** (arXiv 2508.16153, 136+ citations): continual learning for
  LLM agents via case-based reasoning over an episodic memory store — the
  agent retrieves relevant past cases and adapts them; no gradient updates.
- **MemSkill** (arXiv 2602.02474) and **Memento-Skills** (Apr 2026):
  agents learn and *evolve reusable procedural skills* stored as memory,
  with RL-driven skill rewriting — the successor form of skill libraries.
- **"Externalization in LLM Agents"** (arXiv 2604.08224): survey arguing
  the field is moving capabilities out of the model into *memory stores,
  reusable skills, interaction protocols, and harness engineering* — the
  design vocabulary for any 2026 agent build.
- **AWE's two-tier memory** (§C2) is the security-domain instance:
  short-term engagement state + long-term cross-target patterns
  (bypass recipes, sanitization signatures, payload success rates).

**Transfer.** Attackbot's receipts ledger and frontier ledger are already
the short-term tier. The new capability is the **long-term tier**: a
cross-engagement store of (target-feature → effective technique → observed
filter behavior → success rate), consulted by technique-selection and never
auto-executed. That is Memento's case-based reasoning with bug-bounty
semantics, and it reuses the append-only JSONL conventions already in the
platform. The self-evolving variants (RL-rewritten skills) stay parked —
same objection as TheoryCoder-2: the world moves, and frozen autonomous
skills need precondition revalidation the papers don't provide.

**Status: sound with caveats** (curated + retrieval-first; evolution gated
to human promotion — same stance as the first notes, now with a concrete
mechanism to copy).

### C5. Vulnerability intelligence and prioritization

The first notes' open question #5 ("CVE/EPSS ingestion — nobody's scoped
it") now has a mapped solution space:

- **The 2025–2026 prioritization stack**: CVSS (severity) → **EPSS** v3
  (30-day exploitation probability, FIRST) → **KEV** (CISA, confirmed
  in-the-wild) → **SSVC** (SEI/CISA decision tree: Act/Attend/Track) →
  **LEV** (NIST 2025 — probability a CVE has *already* been exploited,
  from EPSS history) → environment-validated proof (commercial: Picus PXS;
  the principle — *evidence beats prediction* — is what our verification
  layer implements for our own findings).
- **The EPSS-lateness finding** (Nucleus research, 18% of Oct-2025–Mar-2026
  KEV additions): median EPSS movement is **121× larger after KEV listing
  than before**; the KEV+2-day spike carries 54% of all EPSS movement; 89%
  within 72h. EPSS confirms risk, it doesn't warn of it. Upstream signals
  that move earlier: public PoC availability, weaponization activity,
  patch availability, media/community attention.
- **Reachability analysis** matured into standard practice (Endor Labs:
  call-graph reachability cuts SCA noise ~95%, combinable with EPSS;
  Google OSV-Scanner call analysis on the open side). For a black-box web
  engine the analogous move is *surface* reachability — which is precisely
  the question the first notes said the SBOM paper couldn't answer
  ("can I reach this vulnerable component through this host's exposed
  surface?").
- **Attack-graph analytics** kept advancing: Palma 2025 (Computers &
  Security) on vulnerable-network-component analysis in attack graphs;
  Bayesian attack graph risk pricing (Variance Journal 2025); a DRL +
  Bayesian hybrid for attack-path assessment (IEEE 2025); Vulnet (learning
  to navigate attack graphs). These *complement* Kuikka's probability
  matrix rather than replace it.

**Transfer.** A CVE-intel ingestion capability should be scoped as:
OSV/GHSA + EPSS API + KEV feed + (PoC-availability and weaponization
signals, which move first and matter most for bug bounty) → join on
CPE/version data from the service-inspection stage → feed both the
chain-candidate generator (CrystalBall slot) and the prioritization layer
(Kuikka slot, with a *multi-signal* prior instead of EPSS-only). The
EPSS-lateness finding changes Kuikka's input design but not the math.

**Status: sound with caveats** — all feeds are public and cheap; the work
is CPE/version normalization against what recon actually fingerprints.

### C6. Attack-technique research the engine's technique library should absorb

The technique frontier moved too; a technique library with a 2024 cutoff
is missing classes that are actively paying bounties:

- **HTTP/1.1 Must Die! The Desync Endgame** — Kettle's fourth wave
  (Black Hat USA + DEF CON 2025): HTTP/1.1 endgame desyncs including the
  **0.CL** technique, with widespread impact reported (T-Mobile, GitLab,
  Netlify cited in coverage) and an explicit industry call to move off
  HTTP/1.1. Builds on "HTTP/2: The Sequel Is Always Worse" (2023) and
  "Browser-Powered Desync Attacks" (2024). Smuggling/desync went from
  "advanced technique" to "class with a four-wave research program" — a
  family of probes (CL.TE / TE.CL / CL.CL / 0.CL / H2 variance /
  browser-powered) that a technique library should hold as *structured
  variants*, not ad-hoc payloads.
- **AI-LLM application surfaces** (OWASP GenAI Top 10): insecure output
  handling (XSS via LLM responses), prompt injection, excessive agency —
  now a standard part of web attack surface as targets ship LLM features.
- **Injection-class pipelines** (AWE): context-mapping and filter-inference
  as *first-class probe outputs* — the observation that payload success
  depends on DOM/template context means the engine should record *context*
  evidence (quoting, sanitization transforms) in the graph, not just
  payload outcomes.

**Status: sound** — practitioner-side, but these are the techniques the
specialized agents (§C2) would encode.

### C7. Evaluation: benchmarks, corpora, and the metric that matters

The first notes' open question #3 ("evaluation corpus before any live
target") is now answerable off the shelf:

- **XBOW benchmark** (104 containerized web challenges, 26 categories,
  flag-on-exploit success criterion) — the de-facto web pentest benchmark;
  every system above reports on it.
- **CVE-Bench** (ICML 2025; real critical web CVEs in sandboxed apps),
  **Cybench** (40 professional CTF tasks), **NYU CTF Bench**,
  **AutoPenBench** (33 tasks, EMNLP industry track), **SEC-bench**
  (real-world software security tasks), plus a 2026 critical review
  cross-comparing them (CTF tasks: reproducible, bounded, simple — good
  for regression, weak for field claims).
- **ARTEMIS real-world study** (arXiv 2512.09882, Stanford/ETH-adjacent,
  Dec 2025): AI agents vs 10 human pentesters on a live enterprise network
  with scope constraints and human triage. ARTEMIS: 2nd overall, 9 valid
  findings, **82% valid-submission rate**, beat 9/10 humans, at lower
  cost. Two transfers: (a) the *valid-submission rate* is the metric that
  made an agent credible — our report layer should be evaluated the same
  way; (b) human-in-the-loop triage with agent-generated evidence is the
  operating model that produced the result.
- **Disclosed-report corpora**: 8K+ public HackerOne disclosures
  (reddelexc/hackerone-reports) and a 2026 empirical taxonomy drawn from
  100+ disclosures (arXiv 2605.25865) — raw material for replay-style
  evaluation ("could the engine have found this?") and for report-quality
  modeling. Caveat: disclosure bias (only successes are public).

**Status: sound.** An evaluation harness is now mostly configuration, not
research: XBOW-style local replicas for regression, CVE-Bench-style
containerized CVEs for the CVE pipeline, disclosed-report replay for field
validity.

### C8. Safety, authorization, and governance

- **"The Ethics of Autonomous AI Agents for Offensive Security"**
  (arXiv 2607.20255, Jul 2026): first dedicated ethics paper; core claims —
  accountability requires logs/approvals/validation evidence, guardrail-
  evasion by agents is a live risk, human oversight must be *governable*
  (interruptible, auditable) rather than nominal.
- **MCP security** became a research area: tool-poisoning attacks
  (Invariant Labs, Apr 2025 — malicious instructions in tool metadata;
  academic follow-up arXiv 2603.22489 / MDPI 2026 found tool poisoning the
  most prevalent client-side MCP threat; CSA calls the protocol's design
  gaps "systemic"; NSA issued a CSI on MCP deployments). Even without MCP,
  the threat class generalizes to *any tool-description-bearing tool
  layer*: an agent that reads tool metadata is prompt-injection surface.
- **Governance gap surveys** (CSA 2026): authorization/identity for agents
  is the acute unsolved area; disclosure-platform policy is being revised
  for AI-submitted reports (human-review requirements expected).
- Practitioner frameworks (Sprocket's safety framework, XBOW's ethics
  post) converge on the same five controls: scoped credentials, budget
  caps, reproducible evidence, human approval gates, graduated autonomy.

**Transfer.** Attackbot's dispatch gate (ALLOW/DEFER/DENY with reasons,
deny-by-default, budgeted) is *ahead* of what most published systems have —
none of the papers above model an authorization regime as strict as ours.
The new obligations from this literature: (1) tool-metadata integrity if we
ever expose tools via a description-based protocol; (2) auditability of
every gate decision (the dispatch log already does this); (3) a policy
answer for AI-submitted reports before the platforms force one.

**Status: sound.** Mostly confirms existing design; adds a threat model
for the tool layer itself.

## 9. What this means for the first list — corrections to carry forward

1. **GoalAct's transcript loop** should be reclassified: the 2026 evidence
   puts difficulty-aware tree search with external state ahead of linear
   replanning for long horizons (§C1). GoalAct remains a valid
   *inside-a-node* propose mechanism — bounded LLM operations on a tree
   need something to propose with.
2. **Observation summarization** (first notes' most load-bearing unbuilt
   piece) is **devalued**: context capacity scaled with the models;
   *structured external state* is the persistent solution. Keep
   summarization only where it must preserve verification-relevant detail
   (headers, timing, content deltas) — that requirement stands.
3. **The missing-bandit gap is closed**: UCB over an attack tree with
   receipt-derived history is published, evaluated, and matches our
   telemetry (§C1). It replaces the first notes' "cheap contextual bandit"
   sketch with something concrete.
4. **The verification gap is closed** by mechanism (§C3), not by paper —
   browser-backed evidence + independent validation agent + quantified PoC
   generation.
5. **Skill synthesis** should be reframed as **case memory** (§C4) —
   cheaper, safer, and the direction the field actually took.
6. **Kuikka stays**, with a multi-signal prior (§C5) and the scale
   caveat unchanged.
7. **The first list's biggest blind spot** — it had no verification, no
   evaluation, no report/triage layer, no intel pipeline — is now the
   *best-covered* part of the literature. The center of R&D weight moves
   accordingly.

## 10. Recommended capability shortlist (evidence-tiered)

Ordered by value-per-effort given the recon side as it stands. This is a
prioritization aid, not a decision.

**Tier 1 — evidence is strong, mechanisms are known, prerequisites exist**
1. **Verification layer**: headless-browser evidence collection + an
   independent validator separated from the proposing agent (AWE §C2,
   MAPTA, §C3). Uses the receipts/dispatch machinery as-is.
2. **Evaluation harness**: XBOW-style local replica set + containerized
   CVE-Bench-style targets + disclosed-report replay; *valid-submission
   rate* as the headline metric (§C7).
3. **Technique-observation schema**: record DOM/template context,
   sanitization transforms, and WAF-filter inference as graph evidence, not
   just payload outcomes (§C2, §C6) — feeds everything downstream.

**Tier 2 — strong evidence, needs a new pipeline**
4. **Difficulty-aware probe selection**: attack tree + UCB over
   (technique × surface) with receipts-derived historical success and
   scorer-derived evidence confidence (§C1).
5. **CVE-intel ingestion**: OSV/GHSA + EPSS + KEV + PoC/weaponization
   signals, CPE-normalized against service fingerprints; unlocks chain
   candidates and prioritization (§C5).
6. **Long-term case memory**: cross-engagement store of
   (target-feature → technique → filter behavior → success rate),
   retrieval-first, human-promoted (§C4).

**Tier 3 — real, but gated on policy or scale**
7. **LLM PoC/template generation** from CVE context (68–72% with
   scaffolding) — gated on the verification layer and on the
   generated-vs-executed distinction (§C3).
8. **Multi-signal probabilistic chain scoring** (Kuikka + LEV-style
   signals) — needs the graph schema and CVE ingestion first.
9. **Specialized exploit agents per vuln class** (AWE-style) — the
   long-run shape; each one is a deterministic pipeline like the recon
   side's, built incrementally per class.

**Explicitly not recommended by this research** (consistent with the first
notes): auto-synthesized skills, autonomous generative payload synthesis
against third-party scope, RL training before trajectory data exists,
EPSS-threshold-only prioritization.
